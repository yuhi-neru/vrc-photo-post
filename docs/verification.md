# 再構築版の検証記録

2026-10-13、日本時間。WPF＋Microsoft WebView2のWindows写真アプリへ再構築。

## 実装済み

- VRCテーマの写真タイル一覧、フォルダ設定、名前検索、複数選択、写真の拡大表示。
- 通常起動で一覧、ファイル引数で写真＋X投稿画面。起動済みアプリへの受け渡し、ドロップ、ダイアログ、ダブルクリック。
- アプリ内Xログインの保持。PNG／JPEGの自動添付、既存下書きの保護、プレビュー検知、エラー表示、二重添付防止。
- Windowsの既定アプリ候補・「プログラムから開く」候補への登録。既定アプリの選択は本人がWindows設定で行う。
- .NETを含むWindows x64配布版。元写真は読み取りのみ。投稿確定の自動操作はない。

## 実機確認済み

- 最新ビルド：警告0、エラー0。Windows x64 self-containedのRelease publish。
- VRCテーマの一覧で8,173枚を索引化。実写真のサムネイル表示を目視確認。以前の確認では検索操作も確認。
- 起動引数で合成PNGを開き、左の写真と右の実際のXを表示。単一起動の引数転送も確認。
- 利用者がXへログインした後、再起動を複数回行ってログイン状態が保持されることを確認。
- **ログイン済みの実際のX（https://x.com/compose/post）に合成PNGが自動添付され、読み込み済み画像プレビューと削除ボタンが表示された。手動の貼り付け・ファイル選択なし。アプリ側も1枚のプレビュー成功を確認。投稿ボタンは押していない。**
- 狭い右パネルではXが全画面形式の投稿画面になる。ダイアログ形式と全画面形式を認識する修正を実施。日本語のメディア削除ボタンにも対応。
- Xの文字数メーターを画像アップロード進捗と誤認した不具合を修正。添付領域に限定して進捗を判定。
- 実WebView2 Runtime 154.0.4258.62で基礎検証9項目が成功。元画像保持、枚数・サイズ上限、HTTPS Xホスト制限、ファイル入力changeイベント、画像デコード、既存添付、誤確認の抑止、4枚プレビュー、文字数メーター付き全画面形式。これらのDOMは自作fixtureで、実Xの4枚検証とは区別する。
- 関連付け起動コマンドは最新版artifacts/release/VrcPhotoPost.exeと引用符付き%1を指す。Windowsの既定アプリは強制変更していない。
- 検証用PNGはXの画面から除去。投稿・ユーザーの既存文章の変更なし。

## 未検証

- 実際の投稿確定。本人がテストする段階。
- 実Xで4枚添付、JPEG、通信切断、期限切れの再ログイン、X側のエラーの全パターン。

## v0.2.0：画像のワールド名と投稿文

- 元画像のXMPのVRChat名前空間からWorldDisplayNameを読み取り、ワールド名＋改行＋`#VRchat`を生成。4枚を選択順に処理して同名を重複させない。名前がない場合はタグのみ。
- 空の新規投稿欄だけに一度入力。WebView2のChromium編集処理でプレーンテキストを挿入し、編集イベントと入力後の文字列を確認。確認できなければ生成文の表示と本人操作のコピーボタンへ案内。
- 元の文章・下書き・添付を保持。待機・再読み込み・写真変更・初期入力後の編集や削除では再入力しない。明示的な「新しい下書き」のみ再設定。ワールド名とタグのチップは本人操作で末尾へ追加し、重複を防止。
- XMLはDTD・外部エンティティを禁止し、チャンク長・展開サイズを制限。接頭辞の別名、RDF属性、日本語・引用符に対応。メタ情報のCRC不一致・破損は名前なしとして扱う。文字列はJSONでエスケープし、実行コードとして扱わない。
- **実機のローカル検証36項目が成功、ビルド警告0・エラー0、Windows x64のpublish成功。** 実VRChat元PNGからワールド名を読み取り、その生成文を空のローカルWebView2投稿欄へ入力。元PNGはSHA-256で変更なしを確認。
- 同名・異名4枚、メタ情報なし・破損・別の名前空間・圧縮データ、編集イベント、入力済み・空白だけの文章、既存添付、チップの重複、複数エディタ、不明な投稿欄、編集済みの空欄、一度だけの初期化を検証。
- 検証中のページはローカルfixtureであり実Xではない。**実Xでの新しい自動文章入力・チップ・React側の入力保持は未検証。** 実Xの画像自動添付はv0.1.1までの別検証。今回、外部への投稿やテスト画像のアップロードは行っていない。
- 実際の再読み込み・写真変更・編集の全操作を実X上で連続実施した検証、実JPEGのメタ情報、全PC環境は未検証。コピーはボタン経由のみで、検証の自動処理ではクリップボードを変更していない。
- `artifacts/probe-final/results.json`が判定記録、`metadata-text-preview.png`が実元PNGから生成した文のローカル投稿欄表示。個人写真・検証画像・プロファイルは公開リポジトリに含めない。

v0.2.1では、起動直後に投稿画面の一部だけが読み込まれた場合も、同じ投稿画面で準備完了を待つよう調整。投稿画面以外で既存エディタの状態が不明な場合は、引き続き画面切り替えと自動入力を止めて保護する。36項目のローカル検証とビルド・publishは再実行して成功。
